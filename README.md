# Time Tracking for Trello

Статический Power-Up для учёта времени и планирования: записи на карточках, бейджи, отчёт по доске, фильтры по датам/меткам/авторам, экспорт в Excel XLSX и лимиты эпиков. Данные хранятся в Trello; отдельного backend и runtime npm-зависимостей нет. Для production-сборки используется только esbuild с зафиксированной версией и lockfile.

Инструкция сверена с официальной документацией **22 октября 2026**. Публикация файлов на хостинге и публикация Power-Up в каталоге Trello — отдельные действия.

## Локальная проверка

Нужен Node.js 22 или новее:

```sh
npm ci
npm run check
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

Открыть `http://127.0.0.1:8080/preview.html`. Это демонстрация с данными только в памяти вкладки, без подключения к Trello. `preview.html?selftest=1` выполняет встроенную проверку интерфейса; демонстрационные даты относятся к октябрю 2026.

`npm run check` запускает функциональные тесты, собирает `dist/` и проверяет полученный коннектор, ссылки, хеши и лимиты размеров. Только сборка: `npm run build`. `dist/` генерируется заново и не коммитится. Исходные HTML/JS также работают без сборки; `npm test` не требует npm-зависимостей.

Автотесты проверяют формат времени, сериализацию, переполнение без потери данных, эпики, отчёт, структуру XLSX и сохраняемый кэш, а также работу контроллера карточки с имитацией SDK: успешное/неудачное сохранение, повторную отправку, права доступа и ошибки обновления после записи. Реальная авторизация, сообщения между iframe и Trello и совместная работа требуют проверки на доске.

## Настройки доски

**Time units** задаёт `1d` в часах, `1w` и `1M` в рабочих днях. По умолчанию: 8 часов, 5 и 20 рабочих дней. `1M` — фиксированная рабочая длительность, `1m` — одна минута. Значения используются при вводе и отображении времени, лимитов и отчётов; сохранённые минуты не меняются.

В **Non-working days** можно выбрать несколько дат, в том числе в разных месяцах. Повторный клик снимает выделение. Раскрываемый список показывает все выбранные даты; **Clear all** очищает его. Эти даты и все субботы/воскресенья пропускаются в прогнозах эпиков. **Week starts on** меняет начало недели в календаре и отчётах, но не набор еженедельных выходных. Изменения применяются через **Save settings**. Подробные пояснения доступны через «?» мышью, фокусом клавиатуры или нажатием; Escape закрывает подсказку.

## Timeline, Depends on и FTE

Кнопка **Time report** на доске открывает общую страницу с вкладками **Time report** и **Timeline**. Данные активной вкладки загружаются при её открытии; выбор периода отчёта и настройки вида Timeline сохраняются при переключении вкладок. Из карточки **Open timeline ↗** открывает эту же страницу сразу на вкладке Timeline с выбранной карточкой в качестве корня. Можно выбрать любой эпик, подэпик или задачу, либо **All projects** для общего пула доски. Выбор корня, даты начала и масштаба **Weeks / Months** меняет представление; сохранять их не требуется. Прогноз планирует только оставшуюся работу, начиная с выбранного дня включительно, с учётом выходных и исключённых дат доски.

**Depends on** доступен под вкладками Epic / Task. **+ add dependency** принимает название или ссылку видимой карточки этой доски; подсказки поддерживают стрелки и Enter. Прямые связи сохраняются в текущей карточке. **Check inherited dependencies** показывает ограничения всех её родителей и ссылки на карточки, где их можно изменить. Эта проверка выполняется по запросу, чтобы обычное открытие задачи по-прежнему не читало журналы всей доски. Timeline загружает полную видимую иерархию автоматически.

Зависимость означает «после завершения всех работ предшественника». Несколько предшественников должны завершиться все. Зависимость эпика распространяется на детей любой глубины, включая добавленных позднее. Проверка перед добавлением Depends on или Child cards учитывает обе разновидности связей и наследование; циклы и зависимость эпика от собственного потомка не сохраняются. Удалить недоступную связь можно без восстановления доступа. Добавление связей требует доступных данных для проверки графа.

**Team availability · FTE calendar** задаёт базовую доступность команды и изменения **From / FTE**. Значение действует с указанной даты до следующего изменения и влияет также на уже выполняющуюся работу. Нажатие на дату на графике добавляет период в редактор; после **Save FTE calendar** прогноз пересчитывается. **Reset** возвращает сохранённый календарь. При 8-часовом дне 0,5 FTE даёт 4 часа работы в рабочий день. Нулевое FTE приостанавливает работу до следующего увеличения. Календарь общий для выбранных проектов доски; выбор отдельного проекта исключает конкуренцию с независимыми проектами за пределами этого представления.

В верхней части карточки **Planning** показывает ETA в одну строку с заголовком и кнопкой редактирования рядом с ним. Нажатие на карандаш открывает все поля; сохранение возвращает превью, а **Cancel** отменяет черновик. В режиме редактирования доступны:

- **ETA** — исходная оценка длительности работы по карточке. Сохраняется вместе с FTE через **Save planning**; пустое поле очищает оценку. Остаток всегда рассчитывается как `max(estimate − spent, 0)` и автоматически уменьшается при добавлении записей времени. Отдельного Remaining work нет.
- **Done в Trello** — завершение отдельной задачи берётся из штатной отметки карточки (`dueComplete`), отдельного чекбокса в Power-Up нет. Снятие отметки возвращает задачу в прогноз. Исчерпанная оценка и нулевой остаток без Done не означают завершения: такой прогноз требует уточнения. Эпик с детьми завершён, когда завершены все дочерние работы; его собственная отметка не отменяет детей.
- **Maximum FTE** и изменения по датам — ограничения карточки и её потомков. Без ограничения задача использует максимум 1 FTE, эпик наследует доступный пул. Значение выше 1 явно разрешает распараллелить одну задачу. Все ограничения родителей действуют совместно; для общей задачи из нескольких веток учитываются ограничения каждого родителя. Это лимиты общего пула, отдельные команды не создаются. Пояснение доступно в подсказке «?» рядом с Maximum FTE.

Порядок Child cards определяет приоритет при нехватке ресурсов, но не делает независимые задачи последовательными. Свободная мощность распределяется в этом порядке; завершение задачи освобождает её и может запускать следующую работу внутри того же дня. Общая задача в нескольких ветках планируется один раз и может отображаться в дереве несколько раз. Даты группирующего эпика определяются дочерними работами; его собственные записи и бюджет не прибавляются к их оценкам. Карточка без детей планируется по собственной оценке за вычетом затраченного времени.

Слева в Timeline находится раскрываемое дерево с датами начала и окончания, справа — полосы и связи. Графики показывают доступную и запланированную FTE по дням. Недоступные карточки, неизвестный остаток, циклы, зависимость от недоступной карточки и работа за пределами горизонта 3650 календарных дней не получают достоверной даты окончания. Остальные независимые работы продолжают рассчитываться. Внешние предшественники выбранного корня включаются в расчёт при наличии доступа на этой доске. Исторический план, отдельные команды, изменения FTE по завершению эпика, Baseline/Accelerated и контрольные точки в этой версии не реализованы.

Формат `time.e`, оценки `time.lim` и Child cards `time.lc` сохранён. Прямые зависимости хранятся в `time.dep`, настройки карточки — в `time.p`, общий календарь — в shared-ключе доски `timeline`. Все записи учитывают существующий лимит shared scope; переполнение не удаляет журналы или чужие ключи. Перед записью календаря перечитываются данные доски и проверяется изменение календаря другой вкладкой. Общие ограничения неатомарной записи Trello остаются в силе. Пользователи без права записи могут менять представление, но не исходные настройки.

`preview.html` содержит пример Project Epic → Epic 1 / Epic 2 → Sub-epic / Task D с зависимостью Epic 2 от Epic 1 и сменой FTE по датам. Функциональные проверки покрывают наследование, циклы, общие задачи, дробное FTE, календарь, ограничения пула, хранение и взаимодействия с UI через DOM-адаптер.

## Скорость и production-сборка

Основная задержка была в загрузке данных: открытие даже обычной карточки читало журналы всей доски. Для каждой пустой карточки выполнялись два SDK-чтения и REST-запрос. Теперь отсутствие ключа после успешного `t.get` считается пустым журналом, как описано в [контракте Trello](https://developer.atlassian.com/cloud/trello/power-ups/client-library/getting-and-setting-data/). При ошибке или некорректных данных остаётся fallback; недоступный журнал не учитывается как достоверный ноль.

Сравнение старого кода и новой версии с одинаковой имитацией SDK: 500 видимых пустых карточек, read-доступ уже разрешён.

| Сценарий | До | После |
| --- | --- | --- |
| Открытие обычной карточки: `t.get` | 1002 | 2 |
| Открытие обычной карточки: REST | 501 | 0 |
| Открытие обычной карточки: `t.cards` | 1 | 0 |
| Чтение журналов всей доски: `t.get` | 1000 | 500 |
| Чтение журналов всей доски: REST | 500 | 0 |
| Список карточек для отчёта: `t.cards` | 2 | 1 |

Эпики сохраняют рассчитанные итоги в shared-данных родительских карточек. При наличии актуального кэша повторное открытие и бейджи читают итог без обхода задач и без получения списка карточек доски. Форма и собственный журнал эпика появляются до получения дополнительных данных. Ошибка загрузки или сохранения кэша не блокирует работу с журналом.

### Сохраняемые итоги эпиков

- Во вкладке **Epic** находится собственный список дочерних карточек Power-Up. Ссылка **+ add child card** открывает форму: начните вводить название и выберите карточку из подсказок либо вставьте `https://trello.com/c/…`, затем нажмите **Add**. Подсказки поддерживают стрелки и Enter; собственная карточка и уже добавленные дети исключены. При одинаковых названиях карточки различаются ссылками. После сохранения, **Cancel** или Escape форма закрывается. Список показывает названия, ссылки и затраченное время даже без лимита. Удаление убирает только связь; карточка и её журнал остаются.
- Порядок дочерних карточек меняется перетаскиванием за маркер слева и сохраняется для всех участников. При фокусе на маркере работают стрелки вверх/вниз. Пока порядок сохраняется, повторное изменение недоступно; при ошибке прежний порядок остаётся.
- При заданном лимите над тонким прогрессбаром высотой 6 px постоянно показаны подсказки со стрелками: затраченное время и остаток. Подписи имеют собственный фон и не перекрывают заливку. Перерасход отображается красным штрихованным сегментом справа с подписью **Over by …**; его доля равна перерасходу относительно всего затраченного времени. Без лимита показывается общая сумма времени.
- Фоновое обновление уже открытой карточки сохраняет интерфейс до получения данных. Если отображаемые данные не изменились, DOM не обновляется. Переключение состояния сохранения не пересоздаёт строки журнала и дочерних карточек; размер iframe обновляется при изменении размера содержимого.
- Связи хранятся в `time.lc` в shared-данных карточки и доступны всем участникам. Встроенные чеклисты Trello не участвуют в расчётах; старые ссылки из них нужно добавить в новый список. Журналы и лимиты сохраняются. Повторные ссылки, ссылка на себя и циклические связи отклоняются. Недоступные карточки остаются в списке с отметкой **Unavailable** и могут быть удалены из эпика.
- `rollup` содержит суммы по непосредственным детям и агрегаты по датам для прогноза; `rollupLinks` хранит прямые и обратные связи. Формат записей времени остаётся совместимым. Время самой группирующей карточки исключается, общая задача в разных ветках учитывается один раз для каждого корневого расчёта.
- Прогноз — сегодняшняя дата плюс остаток `лимит − затрачено`, переведённый в рабочие дни через `hoursPerDay` из настроек доски. Неполный рабочий день округляется вверх. При лимите `4w`, затраченной `1w` и пятидневной неделе остаётся 15 рабочих дней от сегодня. Даты и темп прошлых записей не влияют на расчёт; завтра при том же остатке дата пересчитывается от завтра. Выходные и исключённые даты доски пропускаются, готовая дата не хранится в кэше.
- Добавление, изменение, удаление времени, лимита и связей обнаруживают родителей по сохранённым спискам карточек и обратным связям. Кэши всех предков сначала помечаются неактуальными, затем исходные данные сохраняются и итоги пересчитываются. Общие дочерние журналы читаются один раз в рамках обновления.
- На первом открытии, при изменении списка связанных карточек или через **5 минут** кэш восстанавливается из журналов. Срок проверяется при следующем чтении, фонового таймера нет. Недоступные карточки и циклы не сохраняются как достоверный ноль. Внешние изменения могут оставаться незаметными до истечения срока кэша; серверных webhook здесь нет.
- Метаданные видимых карточек и сохранённые связи загружаются при восстановлении и при сохранении изменений. Для недоступных через SDK журналов остаётся REST fallback с необязательным read-доступом. При открытии с актуальным кэшем эти запросы не нужны.
- Кэш восстанавливаемый и необязательный: при переполнении shared scope он не сохраняется, а перед записью нового времени может удаляться. Журнал и чужие shared-ключи ради кэша не обрезаются. Читатели без права записи используют готовые итоги или расчёт в памяти.
- Перед записью журнала повторно читаются исходные данные; при публикации кэша проверяется токен обновления, чтобы не затирать уже обнаруженное более новое обновление. Это уменьшает конфликты, но не даёт транзакционной гарантии между пользователями: `t.set` неатомарен. Неполное обновление восстанавливается при следующем чтении. После ошибки записи повторные попытки сохранения кэша в этом iframe ограничиваются на минуту, чтобы не создавать цикл `t.render`.
- Дата **Budget finish (1 FTE)** в карточке и отчёте остаётся прогнозом бюджета при 1 FTE; расчёт зависимостей и командной мощности доступен в Timeline. Time report за произвольный период продолжает читать исходные записи и фильтровать их в памяти; общий итог из кэша не заменяет журнал.

Production-страницы содержат один минифицированный локальный JS-файл и, где нужен интерфейс, один локальный CSS. SDK Trello остаётся отдельным внешним скриптом. Коннектор `index.html` не загружает CSS; описание вынесено в `about.html`. Общий внешний `power-up.css` больше не нужен: собственные стили содержат оформление и обе темы. Скрипты запускаются с `defer`; имена JS/CSS содержат хеш содержимого, ручная смена версии при production-сборке не требуется.

| Страница | Локальных JS до → после сборки | JS после минификации | Расчётный gzip |
| --- | --- | --- | --- |
| Коннектор | 8 → 1 | 33,1 КБ | 11,4 КБ |
| Карточка | 12 → 1 | 74,6 КБ | 24,3 КБ |
| Отчёт и Timeline | 14 → 1 | 72,1 КБ | 23,5 КБ |
| Настройки | 6 → 1 | 22,4 КБ | 8,1 КБ |

КБ здесь — 1000 байт, размеры не включают внешний SDK, HTML и CSS. Актуальные размеры каждого файла, gzip и Brotli записываются в `dist/manifest.json`. Сервер должен сам отдавать сжатое содержимое: сборка считает размеры, но не включает сжатие на хостинге. На своём сервере можно задавать длительный `Cache-Control: public, max-age=31536000, immutable` только для `/assets/`; HTML должен регулярно перепроверяться. При публикации в подпапке использовать соответствующий путь `/REPO/assets/`. В GitHub Pages заголовками управляет GitHub.

Это измерения числа обращений и размера файлов, а не обещание конкретного времени открытия Trello. Ранее браузерная проверка собранной версии в Chromium с имитацией SDK покрыла добавление, редактирование, удаление, отчёт на 500 карточках, фильтры без повторного чтения, скачивание XLSX, настройки, preview/selftest и узкий экран с тёмной темой. Объединённые вкладки проверены DOM-тестами.

Вкладки **Epic | Task** переключают отображение: **Epic** содержит лимит, прогресс и дочерние карточки; **Task** — форму добавления времени и журнал с отдельными рамками и отступами для каждой записи. Обе функции доступны одновременно для одной карточки; переключение не меняет данные и сохраняет черновики. Выбранная вкладка не сбрасывается при фоновом обновлении. При открытии карточки с детьми или лимитом выбирается **Epic**, для обычной карточки — **Task**. Для эпика отображаются остаток бюджета и **Budget finish (1 FTE)** (остаток переводится в рабочие дни от сегодня с учётом `hoursPerDay`, выходных и исключённых дат из настроек доски).

## Установка на реальную доску

1. Разместить **содержимое `dist/`** на доступном HTTPS-хостинге после `npm ci && npm run check`. Для GitHub Pages: Settings → Pages → Source → **GitHub Actions**. В репозитории есть `.github/workflows/pages.yml`: pull request проходит проверки; push в `main` или ручной запуск на `main` дополнительно публикует собранный `dist/`. Workflow основан на [официальном шаблоне Pages](https://github.com/actions/starter-workflows/blob/main/pages/static.yml). Проверить успешный deployment и открытие `index.html`, `card.html`, `report.html`, `settings.html`, `auth-complete.html`, `privacy.html`, `about.html` и файлов `assets/` без 404. Корень исходников через Deploy from a branch не использует минификацию.
2. Текущий `origin` проекта — `alexkarpovich/alexkarpovich.github.io`. При публикации корня этого репозитория без custom domain ожидаемый connector URL: **`https://alexkarpovich.github.io/index.html`**. Для обычного project repository адрес имеет вид `https://USER.github.io/REPO/index.html`. Фактический адрес проверить в Settings → Pages.
3. В [Trello Apps Admin](https://trello.com/apps/admin) нажать **New**, выбрать использование Power-Up capabilities, указать имя, Workspace, email, автора и **Iframe Connector URL**. При первом входе портал запрашивает Joint Development Agreement. [Настройка приложения](https://developer.atlassian.com/cloud/trello/guides/power-ups/managing-apps/).
4. Во вкладке **Capabilities** включить ровно эти обработчики:

   | Название | Код |
   | --- | --- |
   | Board buttons | `board-buttons` |
   | Card back section | `card-back-section` |
   | Card badges | `card-badges` |
   | Card detail badges | `card-detail-badges` |
   | Card buttons | `card-buttons` |
   | Show settings | `show-settings` |
   | On enable | `on-enable` |
   | Authorization status | `authorization-status` |
   | Show authorization | `show-authorization` |

5. Открыть тестовую доску **в том же Workspace**, добавить Power-Up через меню Power-Ups (раздел Custom/пользовательских Power-Ups), затем перезагрузить доску. Приватный Power-Up доступен на досках выбранного Workspace; публичное ревью для этой проверки не нужно. [Руководство Trello](https://developer.atlassian.com/cloud/trello/guides/power-ups/building-a-power-up-part-one/).
6. На карточке появятся кнопка **Time** и секция **Time tracking**; на доске — **Time report**. Самостоятельное открытие `card.html` не проверяет интеграцию: странице нужен контекст iframe Trello.

Для разработки лучше отдельный Power-Up и staging URL: изменения production-файлов затрагивают пользователей установленного Power-Up. После обновления перезагрузить доску; при диагностике включить Disable cache в DevTools.

## API key и авторизация эпиков

Обычные записи, связанные карточки и отчёт работают без REST-авторизации. Для восстановления журналов, недоступных через SDK, используется необязательный read-доступ:

1. Apps Admin → приложение → **Trello Auth** → Generate a new API Key.
2. Проверить, что `appKey` в [js/config.js](js/config.js) принадлежит именно этому приложению. В репозитории уже есть публичный ключ; для другого приложения его нужно заменить или оставить пустым. Секреты и пользовательские токены туда не помещать.
3. Настроить Allowed Origins для своего HTTPS origin, например `https://alexkarpovich.github.io`, без пути и без wildcard (OAuth возвращает на `auth-complete.html` того же origin).
4. При первом включении Power-Up откроется **настройки** внутри Trello — нажмите **Connect** в блоке Read access этой панели (не открывайте `settings.html` в новой вкладке). Trello один раз покажет окно согласия; дальше токен хранится в аккаунте. То же можно сделать на эпик-карточке или в отчёте. Запрашивается только `read`. [REST-клиент Trello](https://developer.atlassian.com/cloud/trello/power-ups/rest-api-client/).

Окно согласия возвращается на `auth-complete.html`: внешний `js/auth-complete.js` передаёт результат SDK через `postMessage`, затем SDK сохраняет токен в private member data. Страница завершения не требует iframe-контекста доски. В текущем [SDK Trello](https://p.trellocdn.com/power-up.js) опция метода `authorize()` называется `returnUrl`; `return_url` — имя параметра HTTP-запроса. При обновлении публикуйте весь `dist/`, включая `auth-complete.html` и его файл в `assets/`.

В настройках есть **Disconnect**: удаляет сохранённый SDK-токен. Полное аннулирование разрешения выполняется также в Trello account settings → Applications. При отказе в авторизации основные функции остаются доступными.

## Что проверить на реальной доске

| Сценарий | Ожидаемый результат |
| --- | --- |
| `30m`, `1h 40m`, `1:40`, `1д`, некорректный ввод | Верные минуты; ошибка не создаёт запись |
| Добавление → повторное добавление → редактирование → удаление | Кнопки разблокируются, суммы и бейджи обновляются |
| Двойное нажатие Save / Enter | Одна запись в одном iframe |
| Участник A и участник B | Каждый видит общий журнал; UI позволяет менять собственные записи |
| Наблюдатель / посетитель публичной доски | Нет возможности записи; читаемый интерфейс |
| Эпик с лимитом `2h`; дети с `30m` и `45m` | Остаток `45m`; **Budget finish (1 FTE)** согласован с остатком и настройками рабочего дня; время самого эпика не вычитается |
| Эпик со связанными карточками | Открыта вкладка Epic; Task показывает собственный журнал, обе функции доступны без смены типа карточки |
| Вложенные эпики через Child cards | Время учитывается в итогах предка; лог под-эпика не суммируется в родителя |
| Добавление и удаление `https://trello.com/c/...` в Child cards | Ссылки сохраняются без лимита; повторные и циклические связи отклоняются |
| Удалённый, архивный или перенесённый ребёнок; журнал недоступен | Не показывается недостоверный положительный остаток |
| API key пустой, токен отсутствует, отказ/отзыв разрешения | Основной учёт доступен; неизвестные расчёты явно обозначены |
| Период, автор и метка; пустой/обратный диапазон | Верные суммы; некорректный диапазон блокирует экспорт |
| Экспорт | Excel открывает `.xlsx`, три листа, числовые минуты, нет `NaN` |
| Отказ сети при сохранении и при обновлении после записи | Форма разблокируется; успешная запись не выдаётся за неуспешную |
| Заполнение карточки длинными комментариями | Переполнение отклоняет сохранение, старые комментарии не исчезают |
| Светлая/тёмная тема, узкий popup, клавиатура | Читаемые поля, видимые ошибки, корректный размер iframe |
| Большая доска (например, 500 карточек) | Проверить Network/Performance и отсутствие таймаутов возможностей |
| Две вкладки сохраняют на одной карточке одновременно | Проверить известное ограничение неатомарного shared storage |

В DevTools выбрать iframe Power-Up, проверить Console и Network. Типовые причины: ошибочный connector URL, 404, выключенная capability, доска другого Workspace, Allowed Origins, блокировка auth popup. Заголовки хостинга не должны запрещать встраивание в Trello (`X-Frame-Options: DENY/SAMEORIGIN` этому мешает).

## Публикация для всех пользователей

1. Завершить проверку на реальных досках и стабильном HTTPS-хостинге.
2. Заполнить карточку приложения: Overview, Description, иконку, категории, автора, контактный **Support Email**, доступную **Privacy Policy**; подготовить скриншоты и понятные инструкции тестировщику. Проверить [Public Power-Up Guidelines](https://developer.atlassian.com/cloud/trello/guides/power-ups/public-power-up-guidelines/), включая бренд, скорость и разрешения.
3. В Privacy and Compliance честно описать сохранение member ID, имени автора и комментариев в shared pluginData; отдельно учесть экспортируемые файлы и логи хостинга. Не заявлять «персональные данные не обрабатываются». Требования описаны в [Personal Data Storage](https://developer.atlassian.com/cloud/trello/guides/compliance/personal-data-storage-gdpr/).
4. Подготовить Power-Up ID из URL страницы администрирования и connector URL; отправить заявку через [Trello developer support](https://go.trello.com/dev-support).
5. Пройти review, исправить замечания и согласовать запуск. Документация указывает ориентир **две недели или больше**, без гарантии срока. После одобрения Trello включает публичную доступность; каталог использует адрес `https://trello.com/power-ups/POWER_UP_ID`. [Официальная процедура](https://developer.atlassian.com/cloud/trello/guides/power-ups/submitting-your-power-up/).

Черновик Privacy Policy: [privacy.html](privacy.html) (перед деплоем замените `SUPPORT_EMAIL`). Все поля для Apps Admin и формы review: [SUBMISSION.md](SUBMISSION.md). Остаётся загрузить скриншоты/GIF в портал и пройти проверку на реальной доске.

## Архитектура и ограничения

- `model.js` хранит совместимый компактный формат `time`; существующие записи читаются без миграции. Новые ID используют UUID. `rollup-cache.js` отдельно хранит восстанавливаемые итоги и индекс связей по сохранённым спискам `time.lc`.
- `runtime.js` ограничивает параллелизм и объединяет только незавершённые чтения; завершённые результаты не кэшируются. Повторные уведомления `t.render` сводятся к последовательным обновлениям. Фильтрация отчёта выполняется в памяти без новых запросов.
- Контрольный тест для 100 обычных карточек и 200 одновременных badge/detail-badge callbacks: **101 вызов `t.get` вместо 400**, до 8 одновременно. Это тест с имитацией SDK, а не измерение времени на сервере Trello.
- Просмотр не изменяет pluginData. Ошибки записи и ошибки обновления после успешной записи различаются. При переполнении ничего не объединяется и не удаляется автоматически.
- Trello ограничивает каждую пару scope/visibility **4096 символами**; код оставляет запас, ограничивая JSON до 4000 и учитывая другие ключи того же shared scope. Это не 4 KB в UTF-8. Shared writes неатомарны: защита в одном iframe не устраняет перезапись при одновременной работе нескольких вкладок/пользователей. [Ограничения хранилища](https://developer.atlassian.com/cloud/trello/power-ups/client-library/getting-and-setting-data/).
- Для больших журналов, гарантированной совместной записи и серверного контроля авторства нужен backend с транзакциями. Деление данных на другие ключи того же scope не увеличивает лимит. Экспорт полезен как копия, но импорт/восстановление здесь не реализованы.
- Отчёт использует только видимые карточки открытых списков; архивные не включаются. Если ребёнок эпика недоступен, полный остаток неизвестен. [Семантика `t.cards`](https://developer.atlassian.com/cloud/trello/power-ups/client-library/accessing-trello-data/).
- Записи общие для всех, кто видит доску; на публичной доске они публичны. «Только свои записи» — ограничение интерфейса, не серверная ACL. Не хранить секреты в комментариях. Публичный appKey допустим, пользовательский token — нет. [Security](https://developer.atlassian.com/cloud/trello/guides/power-ups/security/).
- HTML включает CSP для скриптов и no-referrer; пользовательский текст выводится через text nodes. Дальнейшие HTTP-заголовки, TLS, HSTS и возможность встраивания зависят от хостинга и проверяются при развёртывании.
- Экспорт — **XLSX** с тремя листами, числовыми минутами и строковыми ячейками для пользовательского текста. Формулы из комментариев экранируются, недопустимые XML control characters удаляются из содержимого листов.
